# Evidence and fair comparison

## What exists

The application implements exact-catalogue evidence loading, reciprocal rank cues, explicit unknowns, a constraint solver, independent feasibility/objective recounts, proposed note review, immutable publication and a browser UI. Test results and provider observations are recorded separately in VALIDATION.md.

The rehearsal grid is deliberately synthetic and includes real artist names. The twelve privately recorded Qloo rows come from the earlier exact-catalogue investigation; the fresh client preflight exercises the actual API adapter. This is a component demonstration, not a real festival deployment or an availability claim about those artists.

## Three questions

1. **Does the software do what it claims?** Check schemas, coverage, rule derivation, constraints, objective recount, version invalidation and approval. Exhaustive small-instance checks establish an optimum for those instances.
2. **Is Qloo useful evidence for the task?** Compare its pair graph and resulting schedules with strong genre and public artist-similarity sources under matched budgets/common coverage. Show pair intersections, distinctive pairs and missing support. A hand-picked twelve-act set cannot establish general superiority.
3. **Does it help programmers and fans?** Have programmers review proposed changes without being told which signal generated them; compare actual consented attendee must-see conflicts. Association counts are not shared-fan counts. Acceptance by one programmer is useful early evidence, not universal validation.

## LLM-only comparison

Both free-project models receive the same production facts, the same move limit, a request to use their own cultural knowledge and the same JSON output schema. Neither receives Qloo scores or a solver tool. Their schedules are checked with the same independent validator. The comparison also runs the genre-only and Qloo solver under the same hard constraints and time limits.

Report operational errors, actual attendee conflicts, changes and Qloo cue overlaps separately. Do not hide a valid LLM tie or cherry-pick a failed sample. A solver's advantage in constraint compliance is distinct from Qloo's value as an evidence source. Broad genre fields are programmer-declared illustrative inputs, not independently collected MusicBrainz tags.

The existing historical analysis reported 11/14 Qloo edges and 7/9 MusicBrainz-genre edges matching ListenBrainz links. Those near-equal hit rates do not settle Qloo's incremental value. This application does not relabel that historical report as a reproduced experiment.

## Kill or revise

If Qloo's distinctive cues do not lead to accepted changes beyond simpler signals, reduce or retire the Qloo-centered claim. If constraints make a repair impossible, expose the conflict rather than relaxing facts. If a provider fails, report a failed comparison instead of fabricating a result. Actual user benefit remains to be measured on real festival days.
